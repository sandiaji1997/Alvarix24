Introduction

Alvarix SecureAI is a Global AI Risk & Threat Intelligence Platform. Current products are Alvarix Risk API, Alvarix Payment Intelligence, and Alvarix Decision Engine.

Authentication

Use JWT bearer tokens for account, billing, customer, admin, and founder operations. Use `x-api-key` for risk, transaction, payment intelligence, and decision calls.

Authorization: Bearer <jwt>
x-api-key: <api_key>

Generate API Key

Register, log in, then call the API key generation endpoint with a plan value.

POST /api/apikey/generate
Authorization: Bearer <jwt>

{ "plan": "pro", "type": "live" }

Risk API

Score transactions, logins, or API activity with contextual signals.

POST /api/risk-score
x-api-key: <api_key>

{
  "user_id": "usr_123",
  "context": "transaction",
  "amount": 125.5,
  "location": "ID",
  "device": "android"
}

Payment Intelligence API

Add payment-specific context such as method, channel, card country, wallet provider, QR provider, and velocity.

POST /api/v2/payment-intelligence
x-api-key: <api_key>

{
  "user_id": "usr_123",
  "amount": 250,
  "paymentMethod": "card",
  "channel": "ecommerce",
  "cardCountry": "SG",
  "location": "ID"
}

Decision Engine API

Return an approve, review, or block decision from payment intelligence and policy thresholds.

POST /api/v3/payment-decision
x-api-key: <api_key>

{
  "user_id": "usr_123",
  "amount": 250,
  "paymentMethod": "wallet",
  "policy": {
    "blockThreshold": 90,
    "reviewThreshold": 70
  }
}

Billing

Billing endpoints use JWT authentication. Current plan names are Free, Basic, Pro, and Enterprise.

Error Handling

Error responses use `success: false` with an `error` message and optional `details` array.

{
  "success": false,
  "error": "Validation failed",
  "details": ["amount must be a number"]
}

Rate Limits

The platform applies global request limits and plan-level API key limits. Current plan limits are shown on the Pricing page.

Best Practices

  • Keep API keys server-side.
  • Use one API key per environment.
  • Send stable user identifiers, device context, and payment metadata.
  • Log request IDs for support and incident review.
  • Treat high-risk decisions as workflow inputs, not the only control.
